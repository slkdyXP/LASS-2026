# ScopeProbe

ScopeProbe is a broad controlled phenomenon-discovery framework for testing whether textual reflection makes social LLM agents overgeneralize limited evidence across `self`, `specific other`, `world`, and `persona`. It now also contains two candidate mitigation baselines.

## What is controlled

- The same persona and action interface are used across memory baselines.
- `direct`, `full_history`, `summary`, and `reflection` differ only in persistent-memory treatment.
- Twenty-nine scenarios span fishery, water auction, public goods, epidemic coordination, microgrids, teamwork, traffic, and supply chains, plus inferential evidence, salience misdirection, memory-pressure, and entity-binding stress tests.
- A separate, non-persistent probe measures belief attribution at registered checkpoints.
- Every prompt, action, memory snapshot, probe response, expected label, and score is retained.

The current scenarios are synthetic diagnostic vignettes inspired by GovSim and ALYMPICS. Results do **not** establish that the original benchmarks exhibit the same failure until the interventions are integrated into their actual environments.

## Setup

Python 3.10+ is sufficient; there are no third-party runtime dependencies.

Put the key in [`.env`](.env):

```dotenv
DEEPSEEK_API_KEY=your_key_here
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

The `.env` file is ignored by git.

## Validate and smoke-test

```bash
python3 -m scopeprobe validate
python3 -m unittest discover -s tests -v
python3 -m scopeprobe run --dry-run --repeats 1 --workers 2
```

Dry-run outputs are generated by a deterministic mock and must never be used as experimental evidence.

The ordinary-agent baselines are `direct`, `recent_window`, lexical `retrieval`, `full_history`, `summary`, and `reflection`.

The mitigation baselines are:

- `guarded_reflection`: a prompt-only control that prohibits hidden-cause invention and asks for proportional updates;
- `evidence_gated_reflection`: a structured memory that separates persona, current self state, consolidated models, open hypotheses, recent observed episodes, and action policy.

The evidence-gated method keeps single events as episodes or hypotheses, requires repeated or explicitly documented evidence for persistent causal claims, weakens hypotheses after recovery evidence, compresses repeated history, and separates long-term belief consolidation from immediate reversible precautions.

The frozen held-out protocol is in [`configs/scenarios_heldout.json`](configs/scenarios_heldout.json), and its results are summarized in [`HELDOUT_RESULTS.md`](HELDOUT_RESULTS.md). The five-agent closed-loop fishery runner is available through `python3 -m scopeprobe closed-loop`.

## Recommended one-day execution order

First run a live API smoke test on one non-fishery matched pair:

```bash
python3 -m scopeprobe run \
  --scenario public_goods_world_multiplier \
  --scenario public_goods_david_free_rider \
  --baseline full_history \
  --baseline summary \
  --repeats 1 \
  --workers 1
```

Inspect `records.jsonl` for prompt compliance and attribution quality. Then run breadth discovery domain by domain; this prevents one failed large batch from consuming the day:

```bash
python3 -m scopeprobe run --suite breadth --domain public_goods --domain epidemic --repeats 1 --workers 2
python3 -m scopeprobe run --suite breadth --domain power_grid --domain teamwork --repeats 1 --workers 2
python3 -m scopeprobe run --suite breadth --domain traffic --domain supply_chain --repeats 1 --workers 2
python3 -m scopeprobe run --suite inferential --repeats 1 --workers 2
python3 -m scopeprobe run --suite core --suite stress --repeats 1 --workers 2
```

The command prints the estimated number of API calls before starting. Only after inspecting all discovery batches, freeze prompts and repeat the full matrix or a predeclared family-stratified subset:

```bash
python3 -m scopeprobe run --repeats 3 --workers 2 --external-evaluator
```

Each run creates an immutable timestamped directory under `runs/` containing:

- `manifest.json`: exact configuration and scenario snapshot;
- `records.jsonl`: raw prompts, responses, memory snapshots, labels, and scores;
- `errors.jsonl`: failed trials, if any;
- `summary.json`: machine-readable aggregates;
- `report.md`: quick aggregate tables and interpretation gate.

`--external-evaluator` adds a privileged, non-persistent error analysis of the actual memory text, belief probe, and action. It costs one extra model call per checkpoint and is still model-based judgment, not independent human annotation.

Rebuild summaries after manual filtering with:

```bash
python3 -m scopeprobe summarize runs/YYYYMMDD-HHMMSS
```

## Registered interpretation gate

The motivation is supported only if memory baselines repeatedly show:

1. incorrect `primary_scope` or strong protected-scope leakage;
2. worse behavior at the same checkpoints; and
3. the pattern survives prompt auditing and repeated sampling.

The hypothesis should be weakened or rejected if baselines distinguish scope reliably, if errors occur only in the measurement probe, or if belief errors do not affect actions. Action thresholds in `configs/scenarios.json` are provisional and should be reviewed before the confirmatory run.

## Immediate limitations

- The probe is a self-report, not direct access to latent beliefs.
- The scenario text sometimes makes causal evidence explicit; this is useful for the first sanity check but may make the task too easy.
- Summary and reflection require extra model calls and therefore have different compute budgets.
- The matched pairs currently match macro outcomes conceptually, not token-by-token.
- Statistical uncertainty and a model-based external judge are not yet implemented.
